- **Tool schema diet** - analysed Sep 30 2026 and skipped. Tool definitions are ~11.7k tokens per call; the five largest (todoist 6.8k chars, browser 4.9k, garmin_connect 4.7k, garmin_workout 3.9k, generate_image 2.9k) are mostly API reference the model needs on every call (actions, args, filter syntax, edit-op formats). Moving that into skills would force a load round before each integration call (the deferred-loading trap). Compressing the wording in place (repeated "Optional: date_str…" lines, per-action "Requires 'task_id'") could save ~2.5k tokens/call, but those are mostly cached-price tokens, so only ~$2-3/month against ~$1-2 of eval verification. *Trigger:* the Jan 2027 price doubling, or a tool whose description keeps growing.
- **Deferred tool loading** (`find_tools` / `load_tools`) - analysed Sep 30 2026 and not worth it at 26 tools. The integration-tool schemas are ~6.8k tokens per call, but they sit in the explicit context-cache prefix (63% of input tokens were cached-read in Sep; cached input is 1/10 the price), so removing them saves only ~$5-8/month. Each turn needing an integration tool (~540 rounds/month) would pay an extra discovery round that re-sends mostly-uncached history (~$8-20/month) plus latency, and Gemini's cached content includes the tools, so loading them mid-turn forfeits the cache for that turn. *Trigger:* an MCP client (or anything else) pushes the tool count into the dozens. It must then ship with the eval gate: a baseline, not-yet-loaded discovery cases, and selection accuracy held.
