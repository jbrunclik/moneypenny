# Files the Agent Can Work With Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The agent sees its own files in the history, and can take audio and Office uploads.

**Architecture:**
- History lists assistant files like uploads.
- Audio rides the video path (Gemini Files API, `media` block).
- Office bytes become text in `src/utils/office_text.py`, used by the message's file block and by `retrieve_file`.

**Tech Stack:** Python (python-docx, openpyxl, python-pptx, defusedxml), TypeScript frontend.

**Spec:** docs/superpowers/specs/2026-11-16-agent-files-design.md

## Global Constraints

- **Audio types:** `audio/mpeg`, `audio/mp4`, `audio/x-m4a`, `audio/wav`, `audio/x-wav`, `audio/ogg`, `audio/flac`, `audio/aac`.
- **Office types:** docx `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, xlsx `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, pptx `application/vnd.openxmlformats-officedocument.presentationml.presentation`.
- **Limits:** `OFFICE_TEXT_MAX_CHARS` = 100 000; `OFFICE_MAX_UNCOMPRESSED_BYTES` = 100 MB (units in the name, A config rules).
- **Failures:** conversion never raises into the turn. Any failure becomes a text block that names the file and its id for `execute_code`.
- **History bytes** stay stable across turns (no per-turn values).
- **Commits:** Conventional; stage explicit paths only.

## Review Focus

1. **A malicious Office file** (a zip bomb, a huge sheet, a password-protected or corrupt file) gives "could not read", within the caps, and never a 500.
2. **An xlsx with formulas** shows the cached values; when there are no cached values (a file written by a script and never opened in Excel), it shows the formula text and not `None`.
3. **libmagic reads an Office file** as `application/zip` or octet-stream: the upload must still be accepted, and a renamed zip with the wrong MIME must not pass as a PDF.
4. **iPhone m4a** arrives as `audio/x-m4a`: the agent hears it (the Files API accepts that MIME, or it is normalised to `audio/mp4`).
5. **An expired assistant file** is marked `expired` in the history, as uploads are.

### Task 3: Office text

**Files:**
- Create: `src/utils/office_text.py` with `office_text(data: bytes, mime_type: str) -> str`. It raises `OfficeReadError(reason: str)` on any failure.
  - **Zip guard:** `zipfile.ZipFile`, the sum of `file_size` > `Config.OFFICE_MAX_UNCOMPRESSED_BYTES` → error "too large when unpacked".
  - **docx:** paragraphs, with headings as `#` lines; tables as Markdown rows.
  - **xlsx:** `load_workbook(read_only=True, data_only=True)`, then a second pass without `data_only` for cells whose value is None while the formula text exists. Output `## Sheet: name`, then rows as `| a | b |`, skipping empty trailing rows and columns.
  - **pptx:** `## Slide n`, the text of each shape, then `Notes: ...`.
  - **Cap:** stop collecting at `OFFICE_TEXT_MAX_CHARS` (don't build the whole text first).
- `src/config.py`: `OFFICE_TEXT_MAX_CHARS`, `OFFICE_MAX_UNCOMPRESSED_BYTES`, a constant set `OFFICE_MIME_TYPES`, and the allowed types.
- `src/utils/files.py`: aliases for the 3 types (the type itself, `application/zip`, `application/octet-stream`). The zip check: data starts with `PK\x03\x04`.
- `message_content._file_block`: Office → `office_block(file)`, which gives a text block `--- Content of name (Word document) ---` … plus, on truncation, "[... truncated at N characters; open the whole file with execute_code(files=['id'])]". On `OfficeReadError`: `[name could not be read as text: reason. Its id for execute_code: id]`. It uses `history_file_id` when present.
- `file_retrieval._build_file_content`: Office → the same text.
- `history.simplify_mime_type`: "Word document", "Excel spreadsheet", "PowerPoint presentation".
- `requirements.in`: `python-docx`, `openpyxl`, `python-pptx`, `defusedxml` (current majors, capped `<next major`), then `make lock`.
- **Log:** `logger.info("office text extracted", extra={type, chars, truncated, ms, error})`.

**Tests** (`tests/unit/test_office_text.py`; fixtures built in the test with the same libraries):
- A docx with a heading, a paragraph and a 2×2 table → text contains `# Title`, the paragraph and `| a | b |`.
- An xlsx with two sheets, a value and a formula cell with no cached value → `## Sheet: S1`, the value, and `=A1*2`.
- A pptx with 2 slides and notes → `## Slide 2` and `Notes:`.
- A zip whose declared uncompressed size is over the cap (monkeypatch the cap to 1 KB) → `OfficeReadError`.
- Garbage bytes → `OfficeReadError`.
- Text longer than the cap (monkeypatch it to 50) → at most the cap, and truncated flagged.
- `_file_block` for a corrupt docx → the text block names the id; it never raises.

Steps: RED → implement → GREEN → `make test` → commit `feat(files): Office documents are read as text`.
