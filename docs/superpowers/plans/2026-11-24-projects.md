# Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Jiri chose native execution) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Projects are folders of chats with their own instructions, memory and documents.
They can be shared with family members (each member's chats stay private), and the agent
can create projects and move chats into them.

**Architecture:**
- New `projects` and `project_members` tables, plus a nullable `project_id` on
  `conversations`, `user_memories` and `user_documents`.
- Every existing personal query gains `project_id IS NULL`. Project rows are reached
  only through membership.
- A per-turn `# Project:` section in the dynamic context carries the instructions,
  memory and documents, threaded like `StandingContext`.
- Tools find the project from the conversation row; no new contextvar, because
  contextvars don't cross the tool threads.

**Tech Stack:** Flask/APIFlask + Pydantic, yoyo migrations, SQLite, LangChain tools on
Gemini, vanilla TS + Zustand + Vite, pytest, Vitest, Playwright, the eval harness.

**Spec:** `docs/superpowers/specs/2026-11-24-projects-design.md`

## Global Constraints

- Migration `0104_projects` (depends on `0103_user_documents`). Re-check the highest
  number on `main` right before committing it.
- Config (all in `src/config.py`, `.env.example` and docs):
  - `PROJECTS_MAX_PER_USER=30` (owned);
  - `PROJECT_NAME_MAX_CHARS=60`;
  - `PROJECT_INSTRUCTIONS_MAX_CHARS=4000`;
  - `PROJECT_MEMORY_MAX_ENTRIES=60`;
  - `PROJECT_DOCUMENTS_MAX_ENTRIES=20`;
  - `PROJECT_MAX_OPS_PER_CALL=5`.
- **The scope rule:**
  - personal = `user_id = ? AND project_id IS NULL`;
  - project = `project_id = ?` plus membership of the caller.
  - Agent tools reach personal rows plus the **current** chat's project only.
- **Which chats can join a project:** not planning, agent, sports, language, What's new,
  standing or anonymous chats. Mirror `is_ordinary()` in
  `src/agent/tools/instructions_tool.py`, as SQL on those columns.
- `user_id` on project memories and documents = author. Document bytes count toward the
  author's `DOCUMENTS_MAX_TOTAL_BYTES`.
- **Sharing and deleting projects are UI-only.** `manage_project` never adds members
  and never deletes.
- **Logs:** ids and counts only, never names, instructions or memory text. Log lines:
  - "Project created", "Project deleted", "Project member added", "Project member
    removed";
  - "Chat moved to project" (`from`, `to`, `count`);
  - "Project memory write" (`project_id`, `author`, `op`, `source`);
  - "Project context" (`project_id`, `shared`, `chars`);
  - "Project tool" (`op`, `project_id`, `result`).
- Conventional Commits with the `projects` scope.
- Before each commit: `make lint` and the full suite, with exit codes checked directly,
  heavy jobs under `nice -n 10`, and E2E on its own port (`E2E_PORT=8011`).
- Stage explicit paths only.
- UI: test on desktop and at the 768 px breakpoint. Reuse `EmptyState`, `btn btn-*-sm`,
  raised surfaces and icon + label headers. CSS classes use the `project-` prefix. No
  suggestion chips.
- Deploys: after slice A (nothing visible), after Task 13 (B-D together, with the
  projects announcement), and after slice E (with the sharing announcement). B and C
  never deploy alone: the agent could create projects with no UI, or the UI would ship
  without memory.

## Review Focus

1. **A chat moved, or its project deleted or left, while a turn streams.** That turn
   keeps its built prompt. The next turn loads the current state. A tool call naming a
   project memory of a project the chat has since left gets "not found", never a write.
2. **A short id that matches both a personal and a project memory.** The collision is
   reported naming both, never resolved silently to one.
3. **Restoring a chat from the trash whose project was deleted, or whose owner was
   removed from it.** The chat lands in the main list with `project_id` NULL.
4. **Project names and instructions that are Czech, emoji, at the cap, or carry an
   injection pattern from `manage_project`.** Stored intact when clean, rejected with a
   reason when injected, and over-cap text is rejected, never truncated.
5. **A member editing another member's project memory.** The author stays unchanged,
   the edit lands, and the row never appears in the editor's personal list or search.

- Produces: `manage_project(operations: list[dict[str, Any]]) -> str`. It writes inline,

  - `{"op": "list"}` returns `- <8-char id> | <name> | shared|solo | <n> chats`.
